# 게임 카테고리 메뉴 설계 (Game Category Menu)

> 작성일: 2026-06-04
> 대상: ABC Frog 시작화면 메뉴 구조 개편
> 목적: 학습 게임으로서 "배우는 내용" 기준으로 게임을 구분하고, 시리즈 확장에 대비한 메뉴 구조 마련

## 1. 배경 / 문제

현재 시작화면에는 버튼 4개가 한 줄로 나란히 있다: `ABC` · `abc` · `ABc` · `🍎`.

- `ABC` / `abc` / `ABc` → 사실 **같은 게임(파리 잡기)** 의 글자 모양 옵션 3개
- `🍎` → **완전히 다른 게임(과일 단어 퍼즐)**

4개가 똑같은 버튼으로 보여서 "한 게임의 옵션"과 "다른 게임"이 구분되지 않는다.
또한 ABC Frog는 게임 시리즈라 앞으로 게임이 더 늘어날 예정이므로, 확장 가능한 메뉴 구조가 필요하다.

## 2. 분류 기준 (핵심 결정)

이 앱은 **학습 게임**이므로, 게임을 **"노는 방식"이 아니라 "배우는 내용"** 으로 분류한다.
(부모 관점: 3~7세 아이가 무엇을 배우는가)

| 카테고리 | 라벨 | 현재 포함 게임 | 배우는 것 |
|---|---|---|---|
| 알파벳 | **ABC** | 파리 잡기 (ABC/abc/ABc 모드) | A~Z 글자 |
| 단어 | **Word** | 과일 그림 퍼즐 8종 | apple, banana 등 단어 |

오늘 기준으로 두 게임이 각 카테고리에 1:1로 들어맞는다.
앞으로 알파벳 게임이 추가되면 ABC 카테고리에, 단어 게임이 추가되면 Word 카테고리에 넣는다.

## 3. 화면 흐름

2단계 구조: **게임 카드 선택 → (세부) → 게임 시작**

```
[메인 화면 #ss]              [ABC 모드선택 #ms (신규)]        [게임]
 🐸 ABC Frog                  ‹ 뒤로
 ┌─────────────┐             어떤 글자?
 │   🪰        │  ──타치──▶  ┌─────┐ ┌─────┐ ┌─────┐  ──타치──▶  파리잡기 go('ABC')
 │   ABC       │             │ ABC │ │ abc │ │ ABc │           (배경/로직 그대로)
 └─────────────┘             └─────┘ └─────┘ └─────┘
 ┌─────────────┐
 │   🍎        │  ──타치──▶  과일 퍼즐 #wp (지금 그대로, 변경 없음)
 │   Word      │
 └─────────────┘
```

## 4. 상세 설계

### 4.1 메인 화면 (`#ss`) 변경
- 기존 `.mode-buttons` 안의 버튼 4개를 **게임 카드 2개**로 교체한다.
- **ABC 카드**: 그림(`assets/images/fly_front.png`) + 작은 영어 라벨 "ABC"
  - `onclick` → ABC 모드선택 화면(`#ms`)을 연다.
- **Word 카드**: 사과 그림(기존 `appleArt()` SVG 재사용) + 작은 영어 라벨 "Word"
  - `onclick="goWordPuzzle()"` (기존 함수 그대로)
- 카드는 세로로 쌓되, 화면(세로 모드)에 맞춰 가운데 정렬.
- 아이가 알아보는 핵심은 그림이고, 영어 라벨은 부모/학습용 보조. (아이콘은 추후 교체 가능)

### 4.2 ABC 모드선택 화면 (`#ms`) 신규
- 단어 퍼즐 화면(`#wp`)과 동일한 "덮는 오버레이" 방식 (`.show` 클래스로 표시/숨김).
- 구성:
  - 좌상단 `‹ 뒤로` 버튼 → `#ms`의 `.show` 제거 (메인으로 복귀)
  - 제목: "Which letter?" (게임 내 안내 문구가 영어로 통일되어 있으므로 영어로 고정)
  - 큰 버튼 3개: `ABC` / `abc` / `ABc`
- 모드 버튼 클릭 시: `#ms`의 `.show` 제거 후 기존 `go('ABC'|'abc'|'ABc')` 호출.
  - `go()`는 `#ss`를 숨기고 게임을 시작하므로, `#ms` 오버레이만 추가로 닫으면 게임이 정상 표시된다.

### 4.3 단어 퍼즐 (`#wp`)
- **변경 없음.** Word 카드가 기존 `goWordPuzzle()`을 그대로 호출한다.

### 4.4 뒤로가기(popstate) 처리
- 기존 popstate 핸들러는 `#wp`가 열려 있으면 닫는다.
- 동일하게, `#ms`가 열려 있으면 먼저 닫도록 분기를 추가한다 (안드로이드 WebView 뒤로가기 안정성).

## 5. 손대는 파일

| 파일 | 변경 내용 |
|---|---|
| `index.html` | `.mode-buttons` → 게임 카드 2개로 교체, `#ms` 모드선택 화면 마크업 추가 |
| `style.css` | `.game-card` 카드 디자인, `#ms` 화면/모드 버튼 디자인 (기존 `.mbtn`/`.wp` 패턴 재사용) |
| `script.js` | ABC 카드 → `#ms` 여닫기 함수, 모드 버튼 → `go()` 연결, popstate에 `#ms` 분기 추가, `wordBtnIcon` 주입부 → 카드 아이콘 주입으로 조정 |

## 6. 안정성 규칙 준수 (CLAUDE.md)
- 새 함수의 DOM/오디오 호출은 try-catch 또는 `.catch(()=>{})`로 감싼다.
- 새 오디오는 사용하지 않음(메뉴 전환에 효과음 추가 시 `safeAudio()` 사용).
- 전역 에러 핸들러 등 기존 방어 코드는 유지.

## 7. 범위 밖 (YAGNI)
- "곧 추가" 같은 빈/잠금 카드는 지금 넣지 않는다. (게임이 실제로 추가될 때 카드 한 장씩 추가)
- 게임 내용·로직·연출 변경 없음. 이번 작업은 **메뉴 입구 구조만** 바꾼다.
- 기존 `script.js:1535`의 `new Audio()` 안정성 이슈는 이 작업과 별개의 후속 과제로 둔다.

## 8. 성공 기준
- 메인에서 ABC 카드 → 모드선택 → 세 모드 모두 기존과 동일하게 게임 시작.
- 메인에서 Word 카드 → 과일 퍼즐이 기존과 동일하게 시작.
- 모드선택 화면에서 뒤로가기/‹ 버튼으로 메인 복귀.
- 게임 플레이 동작은 변경 전과 100% 동일.
