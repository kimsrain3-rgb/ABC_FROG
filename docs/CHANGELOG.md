- `phoname_n.mp4` → `_source_mp4/phoneme_n.mp4` (원본 보관)
- 소리만 추출 → `_orig_before_boost/phoneme_n.mp3` (음량 손대지 않은 백업)
- `phoname_a.mp3` → `_orig_before_boost/phoneme_a.mp3` (예전 'a' 테이크는 `phoneme_a_take1.mp3`로 **보존**, 덮어쓰지 않음)
- 부스트 → 게임용 `phoneme_a.mp3` / `phoneme_n.mp3`
- 규격 통일: 44100Hz / 스테레오 / 128k / 메타데이터 제거

#### 음량 맞추기 (CLAUDE.md 소리 규칙 준수)
비교 지표는 **RMS**(`ffmpeg -af volumedetect`의 mean_volume) — 1초 미만 짧은 소리라 LUFS는 부정확.
- 기존 기준값: s -16.5dB / t -16.9dB / sat -15.2dB (최고 -0.7~-1.4dB)
- 새 파일 원본: a -20.8dB, n -21.3dB → **4~5dB 작음**. 그대로 넣었으면 "스·트"는 크고 "애·은"은 웅얼거렸을 것.
- `volume=+5.7dB` + `alimiter(limit=-1dB)` 적용 → **결과 a -16.9 / n -16.5dB**, 5종 전부 -15~-17dB대로 정렬.

#### 함정 (다음에 또 걸릴 수 있음)
- **모노 파일을 `-ac 2`로 스테레오 변환하면 ffmpeg가 자동으로 -3dB 감쇠를 넣음**(1/√2 다운믹스 규칙). `phoname_a.mp3`가 모노라 처음에 -24.3dB로 떨어졌음. `volume=3.0103dB`로 정확히 복구함. **모노 소스는 변환 후 반드시 음량 재측정할 것.**
- `phoname_a.mp3`는 44KB 중 **35KB가 앨범아트 등 메타데이터**였음(실제 소리는 8KB). `-map_metadata -1`로 제거.
- ⚠️ 변환 과정에서 **원본 `phoname_a.mp3`는 디스크에서 삭제됨**(git 미추적이라 복구 불가). 소리 차이는 없으나, 새 소리를 넣을 땐 원본을 먼저 `_source_mp4/`나 별도 위치에 복사해 둘 것.

#### 영향 범위
- **파닉스는 아직 `test/phonics/`에서만 쓰임** → 라이브 게임(`index.html`/`script.js`) 무영향.
- `assets/frog/sounds/alphbet_sound.mp4`, `assets/frog/videos/_source_mp4/` 도 발견했으나 **코드에서 참조 없음**(쓰이는 건 `alphabet_sparkle.mp3`, `*.webm`). 이번 작업 대상 아님 — 그대로 둠.

#### 되돌리기
게임용 파일은 `_orig_before_boost/`에서 언제든 다시 부스트 가능. 예전 'a' 녹음은 `_orig_before_boost/phoneme_a_take1.mp3`.

#### (같은 날 추가) 음가 `p`·`i` 도착 → `i` 완료 / `p` 재녹음 요청
- 사장님이 `phoneme_p.mp4`·`phoneme_i.mp4` 추가 (이번엔 파일명 정확). 원본을 **먼저 `_source_mp4/`에 복사한 뒤** 작업(지난 `phoname_a.mp3` 원본 소실 재발 방지).
- **측정법 교정**: 파일 전체 mean_volume은 **무음 패딩이 섞여 부정확**했음(`i`는 전체의 57%가 무음). `silenceremove`로 앞뒤 무음을 걷어낸 **'소리 구간'만의 RMS**로 비교하도록 바꿈. 기존 5종을 이 기준으로 재측정: s -15.8 / a -13.1 / t -15.3 / n -15.0 / sat -14.6 → **목표 = -15dB 부근**.
  - ⚠️ mp3는 인코딩 시 앞뒤에 **완전 무음(디지털 0)** 이 붙음 → 잡음 바닥을 mp3에서 재면 -99dB 같은 헛값이 나옴. **잡음 측정은 원본 mp4에서** 할 것.
- **`i` 완료**: 소리구간 RMS -27.9 → **-16.1dB**, 피크 -1.4. SNR 43.3dB로 깨끗. 리미터가 거의 안 걸리게 **피크 기준으로 게인 산정**(+12.8dB)한 게 주효.
- **`p` 보류 — 녹음 자체 문제**: 목소리 **-31.5dB**(6종 중 최저, `n`보다 12dB 작음) + 방 잡음 **-53.5dB**(6종 중 최대). **SNR 22dB**로 s(39)·t(33)·i(44)보다 10dB 이상 나쁨.
  - 크레스트(피크-RMS)가 21.4dB로 비정상적으로 큼(다른 글자 10~15dB) → 목표까지 올리면 **리미터가 터짐(ㅍ)을 7dB 깎아** 성격이 뭉개짐.
  - **잡음 제거(`afftdn`) nr=12/24/40 3단계 시험 → 개선 1.5dB뿐**(SNR 21.0→22.5). 정상 잡음이 아니라 목소리에 섞인 광대역 노이즈라 제거가 안 됨. **처리로는 해결 불가 = 재녹음이 정답.**
  - 현재는 임시본(-18.4dB, SNR 21) 넣어둠 — 재녹음 도착 시 교체.
- **재녹음 가이드**: ① `n` 녹음 때와 같은 거리·성량(현재 10dB 작음) ② 에어컨·팬 등 소음원 차단 ③ /p/는 파열음이라 마이크를 입 정면에서 살짝 비껴 두기(팝 노이즈 방지).
- **✅ 결정(사장님)**: **현재 `p` 본으로 진행.** 실제로 들어보시고 "괜찮다" 판단. SNR 21dB 수치는 기준 미달이나 **실청 판단이 최종 기준**임(수치는 참고). 재녹음은 언제든 가능 — 파이프라인이 잡혀 있어 파일만 오면 즉시 교체.
  - 남은 리스크(기록용): 조용한 환경·이어폰에서는 "프" 뒤 배경음이 들릴 수 있음. 거슬린다는 피드백이 오면 재녹음으로 해결.
- **결과: satpin 음가 6종 전부 확보 완료** — s -15.8 / a -13.1 / t -15.3 / p -18.4 / i -16.1 / n -15.0 (소리 구간 RMS).
