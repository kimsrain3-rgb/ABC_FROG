## 4. 회선 감지 — 공용 파일 1개에 한 번만

호출 지점 4곳이 **서로 다른 문서**다(공룡·동물·파닉스는 iframe). 변수 공유가 안 되므로 붙여넣기 4번이 아니라 **공용 파일**로 간다 — `error-tracker.js` 가 이미 쓰는 방식 그대로.

```
video-quality.js   ← 새 파일 (저장소 루트)

index.html          : <script>document.write('<scr'+'ipt src="video-quality.js?b='+Date.now()+'">…')</script>
animal.html         : 같음
dino.html           : 같음
phonics/index.html  : ../video-quality.js?b=…      ← 경로 한 칸 위
```

내놓는 것:

| 이름 | 내용 |
|---|---|
| `window.__vq.tier` | `'4g'` \| `'650'` \| `'400'` — **페이지 열릴 때 1회** 계산 |
| `window.__vq.pick(url)` | 그 티어의 주소로 바꿔 돌려준다 |
| `FORCE_ORIGINAL` | `true` 로 바꾸면 **전부 원본** (비상 스위치, 5절 참고) |

### ⚠️ `pick()` 은 허용목록 방식으로 만든다

개구리 액션 클립도 `assets/frog/videos/` 에 같이 살아서, 단순히 `/videos/` 를 치환하면 **webm까지 잡힌다.**

그래서 아래 **네 가지만** 바꾸고, 그 밖의 주소는 **손대지 않고 그대로 반환**한다.

- `assets/dino/videos/…`
- `assets/animal/videos/…`
- `assets/phonics/videos/…`
- `assets/frog/videos/frog-baskit.mp4` (이 파일명 하나만. 같은 폴더의 webm은 제외)

실수로 잘못 불러도 아무 일이 안 일어나게 만드는 것이 목적이다.

### 판정 규칙 (우선순위 순)

1. 주소에 `?vq=650` / `?vq=400` / `?vq=4g` → **그대로 따른다** (검증·폰 확인용 강제 스위치)
2. `connection.saveData === true` → **400** (데이터 절약 모드를 켠 사람)
3. `connection.effectiveType` → `4g`=원본 · `3g`=650 · `2g`·`slow-2g`=400
4. 그 밖 (미지원 · 값 없음 · 예외) → **원본**

판정은 **페이지 열릴 때 1회**만. 재생 중 회선이 흔들려도 영상이 바뀌지 않게 한다.

### 감지 안 되는 기기의 기본값 = 원본

`navigator.connection` 은 **iOS 사파리·파이어폭스가 지원하지 않는다.** 앱은 안드로이드 WebView(크로미움)라 된다.

**기본값을 원본으로 두는 이유**: 감지 실패 시 낮은 화질을 주면 지원 안 하는 브라우저 사용자 **전원이** 이유 없이 나쁜 화질을 본다. 원본이면 **지금과 똑같이 동작**한다 — 즉 "감지 실패 = 기존 동작"이라 새로 나빠지는 경우가 없다.

## 5. 파일명 구분 = 폴더로 나눈다

```
assets/dino/videos/          ← 원본 (그대로, 손대지 않음)
assets/dino/videos_650/      ← dino_trex_movie.mp4   (파일명 원본과 동일)
assets/dino/videos_400/      ← dino_trex_movie.mp4   (파일명 원본과 동일)
```

동물·파닉스도 같은 규칙(`videos_650` / `videos_400`).

**파일명 뒤에 `_650` 을 붙이는 방식보다 폴더가 나은 이유**

- 파일명이 원본과 **똑같아서** 대응 관계가 헷갈리지 않는다
- 한 폴더에 39×3=117개가 섞이지 않는다
- 코드 변경이 **경로 한 조각 바꾸기**로 끝난다. 파닉스는 이름을 조각조각 조립하는 구조(`W.word+'_'+list[k]+'.mp4'`)라 폴더 방식이면 base만 바꾸면 된다
- 한 티어를 **폴더째로 넣고 빼기**가 된다
- 개수 확인이 눈으로 된다(각 10개 / 18개)

※ 폴더 이름의 숫자는 **목표치**다. 실제 크기는 ±10% 범위.

## 6. 압축 방안 (ffmpeg)

### 고정 비트레이트 하나로는 안 된다

길이가 4.0~10.2초로 **2.5배** 차이나서, 같은 비트레이트면 파일 크기가 제각각이 된다.
**파일별로 길이를 재서 비트레이트를 역산한다.**

```
영상비트레이트 = (목표KB × 8 ÷ 길이초) − 소리비트레이트
```

| 티어 | 해상도 | 목표 크기 | 소리 | 예: 4초 / 10초 |
|---|---|---|---|---|
| 650 | 630×1120 | **650,000 byte** | 64k | 1,236 / 456 kbps |
| 400 | 540×960 | **400,000 byte** | **48k** (검수본과 동일) | 752 / 272 kbps |
| 파닉스 | 위와 같음 | 위와 같음 | **`-an` 제거** | 소리 몫까지 그림에 (3단계) |

**용량 단위는 1000 기준이다**(650KB = 650,000 byte). 컨테이너(moov·인덱스) 오버헤드가 있어
**ffmpeg 내부 목표는 이보다 약간 낮게** 잡고, 최종 결과가 목표를 넘지 않는지 확인한다.

### 2-pass 인코딩을 쓴다

2026-08-17 파라사우롤로푸스를 1-pass(`-b:v`)로 했을 때 2,400KB 목표에 **2,248KB(−6%)** 가 나왔다. 2-pass가 목표 크기에 훨씬 정확하다.

공통 옵션: `-c:v libx264 -preset slow` · `-c:a aac` · `-movflags +faststart` · `-vf scale=W:H`
(원본이 720×1280·1080×1920 모두 9:16이고, 630×1120·540×960 둘 다 짝수라 x264 제약 없음)

### 스크립트가 39개를 돌면서

길이 측정 → 비트레이트 계산 → 2-pass 인코딩 → **결과 검사** → 통과한 것만 폴더에 넣는다.

결과 검사 항목: 크기 ±10% / 해상도 정확 / 길이 동일 / 프레임 수 동일 / faststart(`moov` 선두) / 디코딩 에러 0 / 파닉스는 오디오 스트림 0개.
**하나라도 벗어나면 멈추고 보고한다.**

스크립트는 `scratchpad` 에 두고 **저장소에 넣지 않는다.**

**원본 / 650 / 400 을 나란히 붙인 대조 시트**를 만들고 눈으로 본다.

- 대조 시트는 `scratchpad` 에 만들고 저장소에 커밋하지 않는다
- 특히 **10초 넘는 공룡 4개**(브라키오·이구아노돈·스테고·스피노)를 집중해서 본다 — 400 티어에서 검수본보다 12% 낮은 구간

### B. 회선별로 맞는 버전이 나오는지 (본 검증)

1. **가짜 회선 주입** — Playwright로 페이지 열기 **전에** `navigator.connection.effectiveType` 을 `4g`/`3g`/`2g`/`slow-2g` 로 바꿔치기 → 실제 요청 주소가 `videos/` · `videos_650/` · `videos_400/` 로 갈리는지 확인. **감지 코드 자체를 시험하는 것**이라 이게 핵심이다
2. **미지원 기기 흉내** — `navigator.connection` 을 아예 없애고 → **원본**으로 가는지
3. `?vq=` 강제 스위치가 먹는지
4. `saveData=true` → 400 인지

### C. 폴백 확인 (필수)

일부러 **없는 파일**을 가리켜서 → **원본으로 되돌아가 영상이 나오는지.** 이게 통과해야 안심할 수 있다.

### D. 회귀 확인

개구리 액션 클립(webm)이 **손대지 않은 주소로** 나오는지. `pick()` 에 webm 주소를 넣어도 **그대로 반환**되는지.

### E. 라이브

티어별 주소 `curl` 200 + 용량 확인, 실제 라이브에서 화면 캡처.

### F. 폰 (사장님)

`?vq=400` 으로 열어 눈으로 화질 확인 — 특히 **10초짜리 공룡 4개**.
